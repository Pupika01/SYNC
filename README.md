# SYNC — social prototype 0.3

Минималистичный сайт для совместного просмотра с аккаунтами, друзьями и комнатами по пригласительной ссылке.

## Что добавлено в 0.3

- регистрация и вход через Supabase Auth (email + пароль);
- профиль с уникальным ником и отображаемым именем;
- поиск пользователей по нику;
- отправка заявок в друзья, принятие и отклонение входящих заявок;
- список друзей с индикатором онлайн;
- создание комнаты в Supabase и приглашение по приватной ссылке;
- общий список участников комнаты через Supabase Realtime Presence;
- чат и выбор YouTube-видео транслируются участникам комнаты через закрытый Realtime Broadcast;
- Realtime-присутствие и сообщения защищены RLS: в комнатный канал входят только пользователи, принятые по пригласительной ссылке;
- основные настройки Supabase вынесены в `config.js`.

## 1. Подготовь Supabase

Войди в свой Supabase-проект, который уже создавал для SYNC.

1. Открой **SQL Editor** → **New query**.
2. Открой файл `supabase.sql` из этого архива, скопируй весь текст и вставь в редактор.
3. Нажми **Run**. Скрипт создаёт отдельные таблицы `sync_profiles`, `sync_friend_requests`, `sync_rooms`, `sync_room_members`, RPC-функции и RLS-политики. Имена с `sync_` нужны, чтобы не конфликтовать со старыми таблицами комнат и чата в проекте.
4. Открой **Project Settings** → **API** (в некоторых версиях панели — **Data API / API Keys**).
5. Скопируй **Project URL** и публичный ключ **anon / publishable**. Не используй `service_role`, `secret` или любой другой секретный ключ.

## 2. Заполни config.js

Открой `config.js` и вставь значения:

```js
window.SYNC_CONFIG = {
  SUPABASE_URL: "https://ТВОЙ-ПРОЕКТ.supabase.co",
  SUPABASE_PUBLISHABLE_KEY: "sb_publishable_ТВОЙ_КЛЮЧ",
  SUPABASE_ANON_KEY: "", // только для старого проекта, если нет Publishable key
  YOUTUBE_API_KEY: ""
};
```

Для нового проекта используй `sb_publishable_...`. Старый `anon` key тоже поддержан в поле `SUPABASE_ANON_KEY`. Никогда не вставляй `service_role` или `sb_secret_...`: они дают расширенные права и не должны попадать на сайт. Supabase документирует CDN-подключение `@supabase/supabase-js@2` и использование publishable key. См. [установку клиента](https://supabase.com/docs/reference/javascript/installing) и [Realtime Authorization](https://supabase.com/docs/guides/realtime/authorization).

## 3. Настрой подтверждение почты

В Supabase → **Authentication** → **URL Configuration** укажи адрес опубликованного сайта в Site URL и добавь его в Redirect URLs. Для твоего текущего GitHub Pages проекта укажи `https://pupika01.github.io/sync-watch/`. Для локального теста можно добавить `http://localhost:5500/**` или адрес своего локального сервера.

Если включено подтверждение email, после регистрации открой письмо от Supabase и подтверди адрес. Затем войди в SYNC. Проверь, что схема `public` и таблицы `sync_profiles`, `sync_friend_requests`, `sync_rooms`, `sync_room_members` доступны через Data API. SQL уже выдаёт роли нужные GRANT-права, но схема должна быть опубликована в настройках Data API. В Supabase → **Realtime → Settings** оставь включённой авторизацию private channels; когда проверишь работу нового SYNC, можешь отключить **Allow public access**, чтобы весь проект принимал только закрытые каналы (проверь, что другие старые части проекта не используют public channels).

## 4. Опубликуй сайт

Загрузи **все файлы из папки** на GitHub Pages или другой статический хостинг. Важно: `supabase.sql`, `config.js`, `index.html`, `styles.css` и `app.js` должны соответствовать одной версии проекта. SQL-файл запускается отдельно в Supabase и не загружается как страница сайта.

## 5. Проверка

1. Зарегистрируй два тестовых аккаунта с разными никами (например, `alex_07` и `sam_08`). Для второго устройства удобно открыть сайт в другом браузере.
2. С аккаунта Alex найди `sam_08` в разделе «Друзья» и отправь заявку.
3. Войди под Sam и прими заявку.
4. Вернись в Alex и пригласи Sam ссылкой из комнаты.
5. На втором устройстве открой ссылку, войди в аккаунт Sam — он должен появиться в общем списке участников.
6. Отправь сообщение в чат и выбери видео YouTube (для внутреннего поиска нужен отдельный YouTube Data API key).

## Важные ограничения

- Комнаты, профили и заявки используют Supabase. Сам токен приглашения находится в URL и работает как секретная ссылка; не публикуй его открыто, если комната предназначена только для друзей.
- Присутствие друзей и участников комнаты работает через закрытый Supabase Realtime Presence; политики `realtime.messages` разрешают комнатный topic только участникам комнаты. Чат пока передаётся как Realtime Broadcast и не сохраняет историю сообщений после отключения.
- Синхронизируется выбор YouTube-видео. Play/Pause/перемотка пока не синхронизированы.
- Встроенный просмотр пока поддержан для YouTube. Rutube, VK Видео, Netflix и Кинопоиск открывают собственный поиск; защищённое видео этих сервисов нельзя гарантированно встроить в сторонний сайт.
- Username публичен для вошедших пользователей, чтобы поиск друзей по нику работал. Email не отображается в профилях других пользователей.

## Файлы

- `index.html` — структура сайта и формы аккаунта;
- `styles.css` — минималистичный тёмный дизайн;
- `app.js` — авторизация, друзья, presence, комнаты, чат и поиск;
- `config.js` — публичные настройки клиента;
- `supabase.sql` — таблицы, функции и политики доступа для Supabase.
